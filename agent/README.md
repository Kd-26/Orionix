# Customer Agent

**Purpose:** future trusted execution boundary inside customer/provider infrastructure. **Responsibilities:** enrollment/heartbeat/lease/command/workspace/diagnostic interfaces, hardware/model inspection, benchmark and engine supervision boundaries, metrics, capsule metadata, configuration, and health/version metadata. **Non-responsibilities:** networking, credentials, GPU/Docker access, engine execution, optimization policy, provider provisioning credentials, persistence, or deployment today. **Allowed dependencies:** common/config/schemas, feature ports, telemetry, and optional integration ports/adapters at composition. **Prohibited dependencies:** control-plane/web/ORM internals and generic shell execution. **Status:** typed interfaces/configuration/health only. **Next milestone:** implement authenticated outbound protocol state against an in-memory fake transport.
